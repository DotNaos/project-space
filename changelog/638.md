# Deliver Codex messages durably through Workspace Runtimes

Project CLI and MCP callers can now choose a new turn, exact active-turn
steering, or durable queueing when they send a Codex message. Every request
keeps its actor and audit identity, and reusing an operation ID safely replays
the original result instead of dispatching the message twice.

Queued messages survive reconnects and dispatch only after the exact task is
idle on its current generation. Steering requires the current active turn, and
stale or disconnected Workspace Runtime generations cannot receive new work.
The outbound runtime protocol reserves the same owner-, generation-, socket-,
operation-, sequence-, and target-bound identities for the generation-local
Codex host controller.
