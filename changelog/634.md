# Run isolated, recoverable Workspace Runtimes

Project can now start, inspect, suspend, resume, stop, and clean a Workspace
Runtime from the local CLI or through the approved private-network SSH control
path. Both routes use the same strict runtime manifest, exact Workspace
identity, pinned tooling, and generation-fenced ownership checks.

Runtime cleanup preserves the Git checkout and refuses to touch resources that
cannot be proven to belong to the active generation. Interrupted operations are
reconciled from durable evidence, while retired runtime data is moved out of
the active namespace for later privileged reclamation.
