## ADDED Requirements

### ENV-OWN-001 — Owner-preserving built-in aliases

Compute inventory reconciliation MUST retain owner provenance until built-in alias filtering
and reference remapping are complete.

#### Scenario: Cross-owner UUID collision

- **Given** canonical built-in definition `a`, equivalent deployment built-in definition `x`, and user-defined definition `x`
- **When** the user and deployment scopes are reconciled
- **Then** the deployment built-in reference maps to `a`, the user-defined definition and reference remain `x`, and the user evidence is not deleted

#### Scenario: Equivalent built-ins share the same UUID across owners

- **Given** equivalent built-in definitions use the same UUID in the user and deployment scopes
- **When** the combined owner scopes are reconciled
- **Then** exactly one built-in definition remains, both Environment references remain valid,
  and no duplicate-definition violation is introduced

### ENV-OWN-002 — Fail-closed duplicate behavior

Reconciliation MUST preserve existing duplicate and incompatibility violations after owner-safe
canonicalization.

#### Scenario: User definition remains ambiguous

- **Given** the surviving built-in and user-defined definitions share a catalog slug
- **When** the reconciled inventory is validated
- **Then** the user record remains present and the duplicate-slug violation is reported

### ENV-ROUTE-001 — Configured Host selection MUST remain evidence-based

The configured Codex service and HTTP boundary MUST select and retain a physical Host only after
owner-scoped persisted rows have passed through repository reconciliation, and MUST report an
actionable unavailable state otherwise.

#### Scenario: Verified exact Host evidence is available

- **Given** a configured native macOS Environment has verified Host evidence for the exact
  Host `24000000-0000-4000-8000-000000000002` named `os-macbook`
- **When** the configured HTTP boundary starts the task with that exact Host and then sends a
  message to the resulting task
- **Then** both operations use the same owner-bound Environment, the send is accepted, and the
  selected physical machine remains that exact Host

#### Scenario: Host evidence is unresolved or missing

- **Given** persisted rows contain deployment-only, duplicate same-UUID, missing, or conflicting
  Host association evidence
- **When** the configured HTTP start boundary receives the user-owned Host selector
- **Then** the request is blocked with `Select one exact physical machine.` and no start or send
  dispatch is attempted

#### Scenario: Combined projection suppression requires a repaired copy

- **Given** a deployment Tailscale projection shares its UUID with an unresolved, unrelated, or
  user-defined Environment in the user scope
- **When** the combined inventory is presented
- **Then** both records remain visible; suppression occurs only for an equivalent built-in copy
  with resolved identity, manual user evidence, a Host association, and matching copied fields

#### Scenario: An unrelated owner has an equivalent projection

- **Given** an additional non-user scope other than `project-space:tailscale-deployment` contains
  an equivalent projected Environment with the repaired copy's UUID
- **When** the combined inventory is presented
- **Then** the unrelated owner's projected evidence remains visible

#### Scenario: Two connectors match the same Host

- **Given** two matching user-owned connector identities are grouped into the same physical Host
- **When** the ownership backfill evaluates the deployment Environment
- **Then** the two connectors remain distinct candidates and the migration performs no backfill

#### Scenario: The user built-in blueprint differs

- **Given** the matching user built-in differs from the deployment definition in name, operating
  system family, supported architectures, or bootstrap strategy
- **When** the ownership backfill evaluates the deployment Environment
- **Then** the migration performs no backfill
