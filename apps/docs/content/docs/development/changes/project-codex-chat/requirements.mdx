title: Requirement delta

---

## ADDED Requirements

### CHAT-001 — Real Codex conversation

The Chat page MUST render the selected Codex task using the canonical conversation,
approval, input, activity, and continuation behavior.

#### Scenario: Open a task

- **Given** an online machine exposes a real Codex task
- **When** the user selects that task
- **Then** its actual conversation and live task controls appear in the center

### CHAT-002 — Online Tailscale host boundary

The Chat page MUST load Codex sessions only for machines matched to fresh, current, online
deployment-owned Tailscale observations.

#### Scenario: A machine is offline

- **Given** a known Codex machine has an offline or stale Tailscale observation
- **When** the host inventory is refreshed
- **Then** that machine and its tasks are absent from the Chat interface

### CHAT-003 — Grouped compact task navigation

The task list MUST group sessions by machine and MUST show at most four tasks per collapsed
machine section, with an accessible control to reveal or hide the remainder.

#### Scenario: A machine has more than four tasks

- **Given** an online machine has six tasks
- **When** its section is collapsed
- **Then** four tasks and a control for the two hidden tasks are visible

### CHAT-004 — Explicit machine and worktree selection

The Chat page MUST keep machine and worktree selection available and MUST keep the visible
composer disabled until a valid task can be selected from both values.

#### Scenario: No selection yet

- **Given** the Chat page has opened
- **When** no machine and worktree have been selected
- **Then** the composer is visible but cannot submit a message

### CHAT-005 — Task-bound worktree creation

The task detail page MUST create a Codex task only in the Project-managed worktree assigned
to that GitHub issue and MUST NOT offer worktrees assigned to other issues.

#### Scenario: Create from an existing task

- **Given** an existing GitHub issue has an assigned Project-managed worktree on an online machine
- **When** the user opens the new Codex task dialog from that issue
- **Then** the assigned worktree is shown as fixed context and no worktree picker is available

### CHAT-006 — Stored local task discovery

For an eligible online host, the production Chat page MUST list task snapshots owned by the
signed-in user when no direct host transport is available. Live-only actions MUST remain
unavailable until the host transport is reachable. Snapshots already marked missing by a
complete host inventory MUST NOT be presented as locally available tasks.

#### Scenario: Production reads locally published tasks

- **Given** an online Tailscale host has published Codex task snapshots for the signed-in user
- **When** production cannot open the direct host transport
- **Then** the Chat task list shows the current stored tasks, omits missing tombstones, and does
  not enable unverifiable live actions

### CHAT-007 — Task route navigation

Selecting a task MUST open its detail route when the visible project URL is a friendly alias
for the canonical repository catalogue identity.

#### Scenario: Open from a friendly project URL

- **Given** the task list is open at `/projects/project-space/issues`
- **When** the user selects issue 763
- **Then** Project Space opens `/projects/project-space/issues/763`
