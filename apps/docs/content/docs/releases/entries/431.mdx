<ReleaseSummary>
  Foreground connectors can now reach Project Space from proxied containers
  and every connector installation is assigned to an explicit physical or
  virtual machine.
</ReleaseSummary>

## Changes

### Fixed

- The Project CLI preserves only the supported HTTP, WebSocket, no-proxy, and CA variables when it starts a foreground connector.
- The compiled connector routes WebSocket traffic through the configured proxy while honoring standard `NO_PROXY` rules.
- Connection failures now identify proxy, no-proxy, and CA configuration as actionable checks without logging proxy URLs or credentials.
- Machines now have their own primary page and can exist before any connector is installed.
- Connector approval requires selecting an owned machine, or creating a physical or virtual machine first.
- Physical machines can expose configured JetKVM power-on controls; virtual machines never resolve a physical power provider.

### Security

- Unrelated environment variables and unsafe Node runtime switches remain excluded from the connector child process.
- Proxy credentials remain outside command arguments, status output, and connector logs.
- The database backfills legacy connector installations and enforces exactly one machine assignment for every connector identity.

## Upgrade notes

<UpgradeNotes type="required">
  Update the Project CLI, connector, and Project Space server together. The server migration assigns existing connectors to compatibility machines.
</UpgradeNotes>
