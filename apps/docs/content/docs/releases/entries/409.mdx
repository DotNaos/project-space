<ReleaseSummary>
  Every pull request targeting main now owns one validated, versioned
  release entry. Project Docs present those entries as a continuous
  release history with exact Preview and publication identity.
</ReleaseSummary>

## Changes

### Added

- Collapsible Major, Minor, and Patch release navigation inside the existing Docs sidebar
- One continuous article for every minor release line with stable patch anchors and scroll-following navigation
- Compact release sections with summaries, categorized changes, upgrade guidance, and verified publication references
- Exact Docs version or pull request Preview identity on every documentation article
- A trusted post-merge handoff that starts the existing release pipeline from the exact merged commit

### Changed

- Pull requests targeting main must add exactly one valid release MDX file named for the public pull request number
- Preview-only testing guidance is shown only for the matching pull request revision and is omitted from published articles

### Security

- Release MDX is parsed through a constrained content schema that rejects executable expressions, imports, exports, unsafe HTML, images, unsafe links, and placeholder content
- The merge gate rechecks version order, bump consistency, duplicate entries, Git tags, and GitHub Releases against the latest main revision
