<ReleaseSummary>
  Pull request prototypes now require Project Space authentication and
  expose trusted live-development controls only when every repository,
  revision, machine, worktree, task, and lease identity matches exactly.
</ReleaseSummary>

## Changes

### Added

- Exact repository, pull request, Change, surface, viewport, target, and full head revision are preserved through sign-in and return navigation
- Trusted prototype controls show the verified machine, worktree, branch, head, Codex task, and Tailscale development-server lease state
- An exact fresh lease can be opened, while an authorized exact online workspace can start or reuse only its predefined repository development server
- Reviewers can return to the matching changelog Change or the deployed prototype without losing source identity

### Security

- Pull request code never receives terminal access, arbitrary command input, connector or machine credentials, privileged tokens, or direct machine APIs
- Stale, offline, mismatched, unauthorized, ambiguous, or unverifiable evidence fails closed without Start or Open actions
- Privileged requests are attributed to the authenticated Project Space user and the exact repository, pull request, Change, and head revision
