  Pull request feedback is faster for ordinary patches, while release and
  deployment checks now distinguish expected waiting states from real failures.

## Changes

### Changed

- Ordinary patch pull requests use measured Linux verification while release-critical and platform changes retain every platform gate
- Draft pull requests wait for a real numbered release entry before trusted validation starts
- Preview capacity limits remain visible as pending work instead of appearing as product regressions

### Fixed

- Release publication now finishes before exact production delivery can begin
- Preview readiness verifies the public certificate for the exact requested hostname
- Three confirmed timing-sensitive tests now use deterministic completion conditions
- Failed Preview, Release, and Production transitions retain bounded machine-readable evidence

### Security

- Invalid release entries remain unmergeable at their exact pull request revision
- Signing, exact-identity, rollback, health, and full release verification gates remain fail-closed
