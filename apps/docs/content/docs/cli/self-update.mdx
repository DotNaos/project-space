---
title: Self-update
description: Safely check and install a matching signed Project CLI and connector release.
---

`project self-update` checks the signed stable release manifest and keeps the Project CLI and connector on one matching machine-tools release. It only runs when you invoke it; Project does not perform silent or background updates.

If `project --help` does not list `self-update`, your installed binary predates this source command. Follow the guidance for its installation source in [Setup](/docs/setup).

If the mandatory Codex startup command `project agent name --format json` is
missing, run `project self-update --check` before starting the task. A current
CLI distinguishes a real Project Space outage from missing authentication,
unsupported server capability, malformed responses, and an exhausted name
catalog instead of reporting every failure as an offline fallback.

## Check Before Updating

```sh
project self-update --check
```

`--check` verifies the approved release and reports what would happen without changing files.

The normal update flow shows the verified plan and asks for confirmation. The default answer is no:

```sh
project self-update
```

For an explicit non-interactive install:

```sh
project self-update --yes
```

`--check` and `--yes` cannot be combined.

## Optionally Migrate A Homebrew Installation

Homebrew remains a supported way to install and update both tools. Use the
explicit migration flag only when you want to move a supported Homebrew-owned
CLI and connector to the verified managed pair under `~/.local/bin`, without
modifying or removing Homebrew-owned files:

```sh
project self-update --migrate-managed --check
project self-update --migrate-managed
project self-update --migrate-managed --yes
project self-update --migrate-managed --format json
```

Same-version migration remains available because the ownership and service
transition is the requested change. The plan reports the Homebrew source, exact
signed target, managed location, known Homebrew or Project per-user service
transition, preserved machine identity and pairing state, and rollback
behavior. Without `--migrate-managed`, continue using Homebrew for updates;
Project never migrates automatically.

## JSON Automation

```sh
project self-update --format json
project self-update --format json --yes
```

JSON output never prompts. Without `--yes` it is read-only, even when an update is available. The result contains:

| Field | Meaning |
| --- | --- |
| `state` | Final check or update state |
| `installSource` | Detected owner of the installed CLI |
| `currentVersion` | Installed Project CLI version, when available |
| `targetVersion` | Version from the verified approved manifest, when available |
| `migrateManaged` | Whether this is an explicit Homebrew-to-managed migration |
| `managedInstallDir` | Stable per-user destination for the managed pair |
| `serviceTransition` | Known connector service stop, replacement, and readiness proof |
| `preservedState` | Machine identity, protected credential, and pairing state kept outside the release |
| `rollbackBehavior` | Previous service and connector restoration boundary |
| `recoveryCommand` | Exact local recovery command when automatic restoration is incomplete |
| `actionableBlocker` | Safe next step when Project cannot update in place |

Possible states are `current`, `update-available`, `unsupported-source`, `verification-failed`, `update-failed`, `rolled-back`, and `updated`. Unsupported sources and failed verification or installation return a non-zero exit status. A successful check, a current release, or an updated release returns zero.

## Installation Sources

| Installation source | Behavior |
| --- | --- |
| Managed macOS arm64 | Updates the matching CLI and connector pair in place |
| Managed Linux x64 or WSL | Updates the matching CLI and connector pair in place |
| Homebrew without `--migrate-managed` | Remains Homebrew-managed and reports both the normal Homebrew update path and optional migration; never overwrites Homebrew files |
| Homebrew with `--migrate-managed` | Installs the exact signed managed pair under `~/.local/bin`, quiesces the known Homebrew or Project per-user service, prevents it from competing with the managed service, and keeps Homebrew files untouched |
| Native Windows installer | Verifies the release and reports the exact installer URL; never replaces the running executable |
| Source checkout | Reports pull-and-rebuild guidance; never overwrites a development binary |
| Unknown | Refuses to overwrite files and reports reinstall guidance |

## Verification And Rollback

The updater downloads the exact archive named by the signed approved manifest. It verifies the pinned size and SHA-256 checksum before delegating to the existing paired installer. It never trusts a mutable `latest` download URL.

The installer stops the connector, atomically switches both tools, and starts
the connector again when this machine was already connected. Success waits for
nonce-bound authenticated readiness from the exact target build. If startup or
reconnect fails, it restores the previous matching pair and service and reports
`rolled-back`; incomplete service restoration reports `update-failed` with a
local recovery command. Machine identity and credentials live outside the
release directory and are preserved throughout the update or migration.

After an update, verify the local machine normally:

```sh
project --version
project status
project doctor
```
