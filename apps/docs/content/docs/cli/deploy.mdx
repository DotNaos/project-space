## `project deploy`

Deploy the current project to the VPS.

```sh
project deploy [directory] [flags]
```

### Arguments

| Argument | Required | Default | Description |
| --- | --- | --- | --- |
| `directory` | no | `.` | Project directory to deploy. |

### Flags

| Flag | Synonyms | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--host` | - | <span className="doc-type doc-type-string">string</span> | discovered | SSH host. |
| `--path` | - | <span className="doc-type doc-type-string">string</span> | discovered | Remote project directory. |
| `--branch` | - | <span className="doc-type doc-type-string">string</span> | discovered | Git branch to deploy. |
| `--domain` | - | <span className="doc-type doc-type-string">string</span> | discovered | Public project domain. |
| `--api-domain` | - | <span className="doc-type doc-type-string">string</span> | derived from `--domain` when possible | Public API domain. |
| `--email` | - | <span className="doc-type doc-type-string">string</span> | <span className="doc-default-empty">none</span> | Traefik ACME email. |
| `--dry-run` | - | <span className="doc-type doc-type-boolean">boolean</span> | `false` | Print planned remote actions without changing the VPS. |
| `--help` | `-h` | <span className="doc-type doc-type-boolean">boolean</span> | `false` | Print help. |

### Deploy Config

Values can live in `deploy/deploy.yaml`:

```yaml
host: deploy@100.84.238.75
secrets:
  GITHUB_TOKEN: op://projects/GitHub Personal Access Token/token
environments:
  prod:
    default: true
    branch: main
    path: /opt/platform/apps/my-project
    domain: my-project.os-home.net
    apiDomain: api.my-project.os-home.net
  beta:
    branch: beta
    path: /opt/platform/apps/my-project-beta
    domain: beta.my-project.os-home.net
    apiDomain: api.beta.my-project.os-home.net
```

Flags override config.

Deploy status and dry-run JSON include `webUrl`, `apiUrl`, and `docsUrl`.
`docsUrl` is derived from the app domain at `/docs`.

### Behavior

- Requires `deploy/compose.yml`.
- Requires `deploy/ingress.labels.yml`.
- Uses the VPS-owned `private-platform-traefik` ingress and `traefik-public` Docker network.
- Supports only `prod` and `beta`.
- Requires `--env` for deploys.
- Clones or refreshes the remote Git checkout.
- Runs Docker Compose with the deploy compose and ingress labels.

### Examples

```sh
project deploy --env prod --dry-run
project deploy --env beta --dry-run --format json
project deploy status --all-envs --format json
```

## Pull request previews

Preview changes without promoting them to production:

```sh
project deploy preview --pr 263 --format json
project deploy preview status --pr 263 --format json
project deploy preview status --all --format json
project deploy preview destroy --pr 263 --format json
```

Configure `preview.statusHost` in `deploy/deploy.yaml` as a dedicated SSH alias.
The CLI sends only `status-all` through this alias. Its separate SSH key must be
bound to `deploy/preview-status-entrypoint.sh` as the server-side forced command;
do not reuse the mutating Preview deployment key.

Preview deployment and removal are dispatched through
`.github/workflows/deploy-preview.yml` from trusted `main`. Before dispatching,
the CLI verifies the GitHub repository, the PR identity and full head SHA, the
`main` base branch, same-repository branches, and the caller's write permission.
The workflow receives only the action, PR number, and a random operation ID.

`expectedLiveUrl` describes where the preview will be available; it is not live
evidence. Read verified state with `project deploy preview status`. Ready
previews use `https://pr-<number>.projects.os-home.net`.

`status --all --format json` returns `{checkedAt, previews}`. Every preview has
its repository, positive PR number, lifecycle state, and—when runtime evidence
exists—the requested SHA. Running SHA, verified live URL, PR URL, head branch,
timestamps, and message are included only when the trusted registry provides
them. A `removed` or `absent` record can have no SHA when no deployment ever
existed.

## `project deploy status`

Inspect deployment status without changing the VPS.

```sh
project deploy status [directory] [flags]
```

### Arguments

| Argument | Required | Default | Description |
| --- | --- | --- | --- |
| `directory` | no | `.` | Project directory. |

### Flags

| Flag | Synonyms | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `--host` | - | <span className="doc-type doc-type-string">string</span> | discovered | SSH host. |
| `--path` | - | <span className="doc-type doc-type-string">string</span> | discovered | Remote project directory. |
| `--branch` | - | <span className="doc-type doc-type-string">string</span> | discovered | Git branch. |
| `--domain` | - | <span className="doc-type doc-type-string">string</span> | discovered | Public project domain. |
| `--api-domain` | - | <span className="doc-type doc-type-string">string</span> | derived from `--domain` when possible | Public API domain. |
| `--email` | - | <span className="doc-type doc-type-string">string</span> | <span className="doc-default-empty">none</span> | Traefik ACME email. |
| `--help` | `-h` | <span className="doc-type doc-type-boolean">boolean</span> | `false` | Print help. |

### Examples

```sh
project deploy status
project deploy status --host deploy@100.84.238.75 --path /opt/platform/apps/project-space
```
